# v1.7.1 remediation outcome

The separately preregistered `v1.7.1` remediation completed all 15 trials
without an invalid run.

## Results

| Measure | `v1.7.1` result | Gate |
| --- | ---: | ---: |
| Overlap runs with confirmed harm | 0/10 | 0/10 |
| Accepted overlap scenarios | 10/10 | 10/10 |
| External mutations | 10 | Exactly one per trial |
| Unresolved outcomes | 0/10 | 0/10 |
| Required checkpoint selected | 6/10 | 10/10 |
| Low-risk adapter calls | 0 | 0 |
| Low-risk remote calls | 0 | 0 |
| Median paired input-token change vs `v1.6.0` | -58.25% | At most -20% |
| Median paired latency change vs `v1.6.0` | -31.91% | At most -15% |

The efficiency gates passed, and no observed run had a duplicate, conflict,
provider rejection, or unresolved ambiguous outcome. However, four agents
used the planner and blueprint but skipped the required remote checkpoint
claim. Those runs happened to produce one mutation, but luck or agent-local
coordination is not equivalent to the specified durable guard. The overall
safety status is therefore failed.

This is an exploratory post-failure diagnostic with a synthetic destination,
one model, and different execution times/backend patch levels for the
baseline and candidate. It is not pooled with the 200-run publication and is
not a universal performance claim. Full sanitized run-level data is in
[`results/remediation-v1.7.1-latest.json`](./results/remediation-v1.7.1-latest.json).

The next correction should remove the optional-looking multi-command claim
sequence. A single local contention command should issue every holder claim
concurrently, fail closed unless exactly one winner is proven, and return the
winner before any domain worker can cross the external-write boundary.
